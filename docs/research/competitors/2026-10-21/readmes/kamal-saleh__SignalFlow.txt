
# SignalFlow
## The AI Attention Engine for Live Football

SignalFlow is an AI-powered football intelligence prototype that transforms synthetic match events into explainable broadcast insights and audience-aware commentary.

Instead of presenting every match event with equal priority, SignalFlow identifies candidate stories, evaluates their importance and urgency, considers recent story repetition, and determines which insights deserve immediate attention.

The project is designed around a central principle: the same match should provide useful, understandable experiences for general audiences, casual fans, and tactical analysts.

## The Core Pipeline

**Ingest → Interpret → Explain → Render → Personalize**

- **Ingest:** Generate and process synthetic football match events.
- **Interpret:** Detect meaningful patterns and candidate stories.
- **Explain:** Evaluate impact, urgency, evidence, and attention decisions.
- **Render:** Present the match, insights, decisions, and commentary in a live dashboard.
- **Personalize:** Adapt scoring and commentary instructions to the selected audience profile.

## Key Features

### Live Synthetic Match Dashboard
- Animated football pitch with 22 player markers and ball movement.
- Live match clock, score, event stream, and team activity indicators.
- Candidate signals ranked by attention score.
- Current on-air story and an explanation of the attention decision.

### Multi-Agent Intelligence Pipeline
The Analytics project separates match analysis into specialized components:

- **Signal Scout Agent:** Discovers candidate stories from match events.
- **Evidence Verifier Agent:** Checks whether referenced evidence events exist.
- **Importance Agent:** Ranks signals using weighted importance factors.
- **Audience Personalizer Agent:** Adjusts signals according to the selected audience profile.
- **Attention Engine:** Applies attention rules, repetition controls, and decision policies.

The system supports four decisions:

- `SHOW NOW`
- `HOLD`
- `SCHEDULE NEXT`
- `SUPPRESS`

### Audience Personalization
The dashboard supports three audience profiles:

- **General Audience:** Balanced and accessible presentation.
- **Casual Fan:** Simpler, more energetic commentary.
- **Tactical Analyst:** More detailed tactical language when supported by the available events.

### AI-Generated Commentary
SignalFlow uses a local Ollama model to generate natural-language commentary from recent synthetic match events.

The current implementation uses:
- Ollama
- Qwen 2.5 3B (`qwen2.5:3b`)
- A .NET HTTP client service
- Audience-specific prompt instructions
- A lightweight guard for unsupported goal claims

The goal-claim guard is a limited validation layer, not a guarantee that every generated statement is factually correct. Commentary should be evaluated against the recorded match events.

## Prerequisites

- Windows or another supported .NET 10 development environment.
- .NET 10 SDK.
- Ollama installed and running for AI-generated commentary.
- The `qwen2.5:3b` model downloaded in Ollama.

Download the model:

```bash
ollama pull qwen2.5:3b
```

The dashboard can use the local application services, but AI commentary requires Ollama to be available on the machine running the web application.

## Run the Project

Open a terminal in the repository root.

Restore dependencies:

```bash
dotnet restore
```

Run the web application:

```bash
dotnet run --project SignalFlow.Web/SignalFlow.Web.csproj
```

Open the local URL displayed by the ASP.NET Core application.

To generate AI commentary, keep Ollama running and use the **Generate AI Commentary** button on the dashboard.

## Run Automated Tests

Run the test project:

```bash
dotnet test SignalFlow.Tests/SignalFlow.Tests.csproj
```

The tests cover attention decisions, audience personalization, evidence verification, diversity controls, memory behavior, orchestration integration, and goal-claim validation.

## Data and Limitations

SignalFlow uses synthetic football data and does not require real match footage.

The current implementation is a prototype. AI commentary runs locally through Ollama rather than through a publicly hosted AI endpoint. The goal-claim guard covers a limited set of claims and should not be treated as comprehensive verification.

A reviewer running the application must have the required .NET environment and Ollama model available.
